2. Data We Process, and Data We Do Not

PinChat is designed to minimise data processing. What the Service processes and for how long:

  • IP address and User-Agent string — unavoidable technical metadata exposed by any HTTPS request. The application itself does not log access in production (strict privacy mode); however, the hosting provider and any reverse proxy in front of the application may retain access logs containing IP and User-Agent for security and abuse-investigation purposes. See §5 for retention.
  • Session cookie (pinchat_session) — a random, server-side session identifier set after successful login. Strictly necessary for authenticated access; not shared with third parties. HttpOnly, Secure, SameSite=Strict.
  • CSRF cookie — a short-lived, HMAC-signed token used to protect the login form against cross-site request forgery. Strictly necessary; cleared immediately after login.
  • Room metadata (room UUID, type, time-to-live, max participants, participant count) — held exclusively in server memory for the life of the room; never written to disk. Deleted automatically when the room expires or becomes empty.
  • Proof-of-Work challenge cache — an HMAC over your IP address, stored in memory for a few minutes, used to rate-limit room creation and WebSocket token issuance. Deleted on challenge consumption or expiry.

What the Service does not process:

  • Message content. Messages are end-to-end encrypted in your browser with a symmetric key that never leaves your device (it is transmitted to other participants only through the room URL fragment, which is never sent to the server by design). The Controller cannot read your messages and does not store them on disk; they live only in server memory for the milliseconds needed to relay them.
  • Accounts or profile data. No registration, no name, no phone, no email collected from users of the Service.
  • Analytics, trackers, or advertising cookies. None are used.

7. Automated Decision-Making

8. Security

Technical measures in place include: HTTPS/TLS, Argon2id password hashing for beta access, HMAC-signed CSRF tokens with constant-time verification, single-use short-lived JWT tokens for WebSocket upgrade, proof-of-work to limit automated abuse, rate limiting, and end-to-end encryption of message content. The application runs in a container with non-root privileges and dropped Linux capabilities. Despite these measures, as noted on the homepage, the Service has not undergone a formal third-party security audit and may contain vulnerabilities.
