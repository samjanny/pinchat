Group rooms run a custom MLS/TreeKEM implementation verified against the IETF reference vectors for ciphersuite MLS_128_DHKEMP256_AES128GCM_SHA256_P256. MVP scope is 2 members per room while 3+-member support stabilises.

How the link works

Your room URL looks like /c/<id>#key=<b64>. The fragment after # stays on the client — RFC 3986 — so the server never sees the symmetric key.

What the server sees

A room ID, a TTL, and opaque encrypted payloads. No message content, no metadata, no persistent identifier tying sessions together.

Identity verification

Before any message goes through, you'll see a Short Authentication String — 8 emoji derived from both parties' identity keys. Confirm it out-of-band to rule out MITM.

End-to-End Encryption
Only you and your contacts can read the messages. The server only relays ciphertext.
No accounts
No registration, no personal data, no persistent identifier across sessions.
No persistence
Messages are never stored on disk. Server keeps only in-RAM state until the room TTL.
Auto-destruction
Rooms delete themselves at expiration. Short or long — you decide up front.
Open Source
Code is publicly auditable on GitHub. Reproducible Docker builds.

Important notes

  • Do not share the room link on public channels.
  • The encryption key is contained in the link (after the # symbol).
  • If you lose the link, you can no longer access the chat.
  • Messages cannot be recovered after the room expires.

Experimental software — use at your own risk

PinChat is an experimental prototype provided strictly for educational and research purposes. It is NOT designed, intended, or warranted for production use, the protection of real-world sensitive, personal, financial, or confidential data, or safety-critical, life-critical, or mission-critical communications.

Although it uses modern cryptographic techniques, it has not undergone a formal security review or audit, and may contain serious vulnerabilities. You can audit the code yourself on GitHub.
